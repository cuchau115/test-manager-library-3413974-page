Manager Library

Sitio público estático de presentación del sistema de gestión de biblioteca construido guiado por especificación (SDD) y traducido a React + Laravel + PostgreSQL sobre Docker.

Conocer el proyecto Cómo correrlo

Qué es

Un sistema para la biblioteca pequeña

Manager Library permite a una biblioteca pequeña llevar su catálogo de libros, sus socios y sus préstamos, y ver qué libros se prestan más. Nace de una especificación (spec) y se construye guiándola paso a paso: primero la arquitectura, luego el código.

Catálogo

Libros con título, autor, ISBN de 13 dígitos, categoría, ejemplares totales y disponibles, y portada opcional (JPG/PNG, máx. 2 MB). Las cinco categorías son fijas.

Socios y préstamos

Socios con nombre y documento único. Un préstamo es de un socio, trae de 1 a 3 líneas, descuenta un ejemplar por línea y vence a los 14 días.

Control y reportes

Devolución por línea, libros vencidos y reporte de los más prestados por rango de fechas, con los valores congelados en el momento del préstamo.

Qué construye el spec

Diez historias de usuario

La especificación define los actores (administrador y bibliotecario), las reglas de negocio, el modelo de datos y el contrato HTTP. Todo se implementa respetando el negocio y traduciendo la tecnología a React + Laravel.

  1. HU-01 Iniciar sesión token de 8 h; sin token 401, rol insuficiente 403
  2. HU-02 Dar de alta bibliotecarios solo admin; usuario en minúsculas y único
  3. HU-03 Gestionar libros ISBN único, total ≥ 1, baja lógica
  4. HU-04 Buscar libros texto, categoría, activos, paginado (máx. 50)
  5. HU-05 Gestionar socios documento único; no se eliminan
  6. HU-06 Registrar préstamo 1–3 líneas, sin repetir libro, máx. 3 sin devolver
  7. HU-07 Registrar devolución una línea; nunca suma dos veces
  8. HU-08 Ver y listar préstamos estado calculado: open, overdue, closed
  9. HU-09 Libros vencidos ordenados por días de retraso
  10. HU-10 Reporte de más prestados por rango; rango invertido 422

Stack

Tecnología del reto

El spec original está escrito para Python y .NET; el reto se construye en React y PHP/Laravel, empaquetado con Docker. La arquitectura es hexagonal: el dominio no depende de nada y los puertos los define la aplicación.

  • React 18 + VitePanel de gestión (frontend)
  • PHP 8.3 + Laravel 11API y reglas de negocio
  • PostgreSQL 16Base de datos (esquema library)
  • JWT HS256Autenticación y roles
  • Docker + ComposeUn solo comando levanta todo
  • Arquitectura hexagonalDominio, puertos y adaptadores

Cómo correr

Un comando desde infra

Con Docker Desktop en marcha, todo el sistema se levanta con un único comando. La API aplica las migraciones y crea el administrador inicial desde el entorno.

cd infra
docker compose up --build
  • page — este sitio público estático (no usa la API).
  • app — panel de gestión en React.
  • api — backend Laravel en /api/v1.
  • db — PostgreSQL 16 con el esquema library.
